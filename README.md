## Требования

На **обеих** машинах (сборочной и целевой):

- **Python 3.8+** — скрипты используют только стандартную библиотеку.
- **Docker** — [Docker Desktop](https://www.docker.com/products/docker-desktop/) для Windows/macOS или `docker` + `docker compose` для Linux.
- **Node.js и npm** — только на сборочной машине (для `npm install` во frontend).

Проверить:

```bash
python --version
docker --version
docker compose version
npm --version    # только на сборочной
```

## Состав комплекта

| Файл         | Назначение                                                           |
|--------------|----------------------------------------------------------------------|
| `build.py`   | Собирает контейнеры проекта (`docker compose up --build`).           |
| `export.py`  | Сохраняет все образы из `docker-compose.yml` в один `.tar`-архив.    |
| `import.py`  | Загружает `.tar`-архив и запускает контейнеры на целевой машине.     |
| `Import/`    | Папка для передачи архива и сопутствующих файлов на целевую машину.  |

## Структура папок

Сборочная машина (там, где есть исходники и интернет):

```
project/
├── frontend/
├── backend/
├── infra/
├── docker-compose.yml
└── .env
```

Машина, где лежат скрипты:

```
offline-kit/
├── build.py
├── export.py
├── import.py
├── README.md
└── Import/                ← сюда export.py положит архив
```

Целевая машина (куда переносится папка `offline-kit` целиком):

```
offline-kit/
├── export.py
├── import.py
├── README.md
└── Import/                ← здесь лежат .tar, .env и infra/
    ├── exported.tar
    ├── .env
    └── infra/
        └── nginx/
            ├── nginx.conf
            └── certbot/
                ├── conf/
                └── www/
```

## Сценарий работы

### 1. Сборка (на машине с интернетом и исходниками)

Запусти `build.py` и укажи путь к проекту:

```bash
python build.py
```

Скрипт:

1. Проверит наличие Docker.
2. Спросит путь к папке проекта (по умолчанию — папка, где лежит сам скрипт).
3. Выполнит `npm install` в `<проект>/frontend`.
4. Проверит наличие `docker-compose.yml` или `compose.yaml`.
5. Запустит `docker compose up --build`.

После успешного завершения все образы будут собраны и запущены. Останови контейнеры (Ctrl+C), они больше не нужны — образы остались локально.

### 2. Экспорт образов

Запусти:

```bash
python export.py
```

Скрипт:

1. Спросит путь к папке проекта.
2. Если рядом со скриптом есть папка `Import` — **автоматически сохранит архив туда** под именем `<имя_папки_проекта>.tar`.
3. Если папки `Import` нет — спросит путь к `.tar`-файлу вручную.
4. Соберёт список образов из `docker-compose.yml`, проверит что все они есть локально.
5. Выполнит `docker save --platform linux/amd64 -o <output>.tar <images>`.

### 3. Импорт и запуск (на целевой машине)

1. Перенеси **всю** папку `offline-kit` на целевую машину (флешка, scp, что угодно).
2. Убедись, что в `Import/` лежат:
   - `*.tar` — архив с образами;
   - `.env` — **обязательно** (см. следующий раздел);
   - `infra/` — **обязательно** (см. следующий раздел).
3. Запусти:

   ```bash
   python import.py
   ```

Скрипт:

1. Найдёт `.tar` в своей папке (если их несколько — возьмёт первый и предупредит).
2. Выполнит `docker load -i <архив>`.
3. Проверит, что на месте `.env` и `infra/nginx/nginx.conf`.
4. Запустит `docker compose up -d`.
5. Покажет статус контейнеров.

Готово — проект работает без интернета.

## Что обязательно перенести в папку `Import`

> ⚠️ **Без этих файлов `import.py` не сможет запустить проект, даже если образы загрузились.**  
> Образы — это только код и зависимости. Настройки и конфиги nginx — снаружи и передаются отдельно.

### 1. Файл `.env`

Содержит переменные окружения для backend, celery и базы:

```
POSTGRES_DB=...
POSTGRES_USER=...
POSTGRES_PASSWORD=...
SECRET_KEY=...
DEBUG=0
ALLOWED_HOSTS=...
# и другие переменные проекта
```

Берётся из корня оригинального проекта — **тот же самый**, что использовался при сборке. Убедись, что в нём заданы переменные подключения к внешним API (см. раздел «Возможные проблемы», пункт про `No connection adapters`).

`import.py` проверяет наличие `.env` и завершится с ошибкой, если файла нет.

## Кратко

| Шаг | Команда                | Где запускать                |
|-----|------------------------|------------------------------|
| 1   | `python build.py`      | машина с исходниками и сетью |
| 2   | `python export.py`     | там же                       |
| 3   | *перенести папку*      | на целевую машину            |
| 4   | `python import.py`     | целевая машина               |

**Не забыть перенести в `Import/`:** `.env`, `infra/` и сам `.tar`-архив.
**Не забыть положить рядом с `import.py`:** offline-версию `docker-compose.yml`.
