# DockerAutomation: Скрипты для сборки, экспорта, загрузки и запуска Docker-проекта

## Введение

Набор скриптов предназначен для автоматизации работы с Docker-проектом:
- сборка и запуск контейнеров;
- экспорт Docker-образов в единый `.tar`-архив;
- загрузка образов из архива и запуск контейнеров;
- простой запуск уже собранных контейнеров.

Скрипты поддерживают **Windows** (через `.bat` и `.ps1`) и **Linux/macOS** (через `.sh`).  
Они упрощают развёртывание проекта на разных машинах, в том числе в офлайн-среде, когда нет доступа к интернету или репозиторию.

---

## Требования

- **Docker Desktop** (или Docker Engine + плагин Compose)  
  Скачать: [https://www.docker.com/products/docker-desktop/](https://www.docker.com/products/docker-desktop/)
- **Node.js и npm** — для сборки frontend (шаг `npm install`)
- **Windows**: PowerShell (встроен в систему)
- **Linux/macOS**: bash

---

## Состав скриптов

| Скрипт | Платформа | Назначение |
|--------|-----------|------------|
| `build.sh` | Linux/macOS | Сборка и запуск проекта |
| `build.bat` + `build.ps1` | Windows | Сборка и запуск проекта |
| `export.sh` | Linux/macOS | Экспорт Docker-образов в `.tar` |
| `export.bat` + `export.ps1` | Windows | Экспорт Docker-образов в `.tar` |
| `load.sh` | Linux/macOS | Загрузка образов из `.tar` и запуск |
| `load.bat` + `load.ps1` | Windows | Загрузка образов из `.tar` и запуск |
| `run.sh` | Linux/macOS | Запуск контейнеров |
| `run.bat` + `run.ps1` | Windows | Запуск контейнеров |

## Описание скриптов

### build — сборка и запуск

**Файлы:** `build.sh`, `build.bat`

**Что делает:**
1. Проверяет наличие Docker.
2. Запрашивает путь к проекту (по умолчанию — папка, где лежит скрипт).
3. Переходит в подпапку `frontend` и выполняет `npm install`.
4. Проверяет наличие `docker-compose.yml` или `compose.yaml`.
5. Запускает `docker compose up --build`.

**Использование:**
- Linux/macOS: `./build.sh`
- Windows: запустить `build.bat` (двойным кликом или из консоли)

Скрипт задаст вопрос о пути к проекту. Можно нажать Enter, чтобы использовать папку скрипта, или ввести свой путь.

---

### export — экспорт образов

**Файлы:** `export.sh`, `export.bat`

**Что делает:**
1. Запрашивает путь к проекту (где находится `docker-compose.yml`).
2. Запрашивает путь для сохранения `.tar` (по умолчанию — папка скрипта, имя файла = имя папки проекта).
3. Собирает список образов из `docker compose images`.
4. Сохраняет все образы в один `.tar` с помощью `docker save`.

**Использование:**
- Linux/macOS: `./export.sh`
- Windows: `export.bat`

**Важно:** перед экспортом образы должны быть собраны (например, с помощью `build` или `docker compose build`).

---

### load — загрузка образов и запуск

**Файлы:** `load.sh`, `load.bat`

**Что делает:**
1. Ищет `.tar`-файл в папке, где лежит скрипт (если файлов несколько, берёт первый).
2. Загружает образы из архива (`docker load`).
3. Дополнительно подтягивает `redis:7` и `nginx:alpine` из интернета.
4. Проверяет наличие `.env` и `infra/nginx/nginx.conf`.
5. Запускает контейнеры в фоне: `docker compose up -d`.
6. Показывает статус: `docker compose ps`.

**Использование:**
- Поместите `load.sh` (или `load.bat`/`load.ps1`) и `.tar` в папку проекта (где `docker-compose.yml`, `.env`, `infra/nginx/nginx.conf`).
- Linux/macOS: `./load.sh`
- Windows: `load.bat`

**Важно:** скрипт ожидает, что все необходимые файлы проекта уже находятся в этой папке.

---

### run — запуск контейнеров

**Файлы:** `run.sh`, `run.bat`

**Что делает:**
1. Переходит в папку, где лежит скрипт.
2. Выполняет `docker compose up -d`.
3. Показывает статус: `docker compose ps`.

**Использование:**
- Поместите скрипт в папку проекта.
- Linux/macOS: `./run.sh`
- Windows: `run.bat`

---

## Общие замечания

- Все скрипты для Windows используют `.bat` как обёртку для `.ps1`, чтобы обеспечить запуск двойным кликом и обход политики выполнения.
- В скриптах предусмотрена обработка кавычек и пробелов в путях.
- Для работы `load` и `run` скрипты должны находиться в папке проекта (рядом с `docker-compose.yml`).
- `build` и `export` могут находиться в любом месте, так как запрашивают путь к проекту.
- Убедитесь, что у вас установлены Docker, Docker Compose, а также Node.js и npm для сборки frontend.

## Примеры использования

### Сценарий 1: Сборка и запуск на локальной машине

1. Запустить `build.sh` (Linux/macOS) или `build.bat` (Windows).
2. Указать путь к проекту (или нажать Enter, если скрипт в папке проекта).
3. Дождаться сборки и запуска.

### Сценарий 2: Перенос проекта на другую машину без интернета

1. На машине с интернетом и исходниками:
   - Запустить `build.sh`/`build.bat` для сборки.
   - Запустить `export.sh`/`export.bat`, указать путь к проекту и сохранить `.tar`.
2. Скопировать `.tar` и папку проекта (или только необходимые файлы: `docker-compose.yml`, `.env`, `infra/`) на целевую машину.
3. На целевой машине:
   - Поместить `load.sh`/`load.bat` и `.tar` в папку проекта.
   - Запустить `load.sh`/`load.bat`.
   - Контейнеры будут загружены и запущены.

### Сценарий 3: Просто запустить уже собранные контейнеры

1. Поместить `run.sh`/`run.bat` в папку проекта.
2. Запустить скрипт. Контейнеры запустятся в фоне.

## Устранение неполадок

- **Docker не найден** — установите Docker Desktop и убедитесь, что он добавлен в `PATH`.
- **`docker compose` не работает** — проверьте, что установлен плагин Compose (в Docker Desktop он встроен).
- **Ошибка `npm install`** — убедитесь, что установлен Node.js и npm, а в папке `frontend` есть `package.json`.
- **Не найден `.env` или `nginx.conf`** — создайте их вручную или скопируйте из репозитория.
- **Несколько `.tar` файлов** — скрипт `load` использует первый найденный; при необходимости оставьте только нужный архив.
