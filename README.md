# README

Данный набор скриптов предназначен для автоматизации сборки, экспорта, загрузки и запуска Docker-контейнеров проекта. Все скрипты написаны на PowerShell и имеют парные `.bat`-файлы для удобного запуска в Windows.

## Требования

- Операционная система Windows
- PowerShell (встроен в Windows)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) с поддержкой `docker compose`
- Node.js и npm (для сборки frontend)

## Описание скриптов

Все `.bat`-файлы являются обёртками, которые запускают соответствующие `.ps1`-скрипты с необходимыми параметрами. Они также обрабатывают код возврата и приостанавливают работу окна после завершения, чтобы вы могли увидеть результат.

### build.bat / build.ps1

**Назначение:** Сборка проекта.

**Что делает:**
1. Запрашивает путь к директории проекта. По умолчанию предлагается папка, в которой находится сам скрипт.
2. Проверяет наличие Docker в системе.
3. Переходит в подпапку `frontend` и выполняет `npm install`.
4. Проверяет наличие файла `docker-compose.yml` или `compose.yaml`.
5. Запускает `docker compose up --build`.

**Использование:**
Запустите `build.bat` и следуйте подсказкам в консоли. Если путь не указан, будет использована папка скрипта.

### export.bat / export.ps1

**Назначение:** Экспорт Docker-образов в tar-архив.

**Что делает:**
1. Запрашивает путь к проекту (где находится `docker-compose.yml`).
2. Запрашивает путь для сохранения `.tar`-файла. По умолчанию предлагается имя, совпадающее с именем папки проекта, в директории скрипта.
3. Получает список образов с помощью `docker compose images`.
4. Сохраняет все образы в один архив с помощью `docker save`.

**Использование:**
Запустите `export.bat` после успешной сборки. Полученный `.tar`-файл можно перенести на другую машину.

### load.bat / load.ps1

**Назначение:** Загрузка образов из tar-архива и запуск контейнеров.

**Что делает:**
1. Ищет `.tar`-файл в папке скрипта. Если файлов несколько, используется первый, а остальные выводятся в предупреждении.
2. Загружает базовые образы `redis:7` и `nginx:alpine` (если они отсутствуют).
3. Выполняет `docker load -i <tar-файл>`.
4. Проверяет наличие файла `.env` и `infra\nginx\nginx.conf`.
5. Запускает `docker compose up -d`.

**Использование:**
Поместите экспортированный `.tar`-файл в ту же папку, где находятся скрипты, затем запустите `load.bat`.

### run.bat / run.ps1

**Назначение:** Запуск контейнеров.

**Что делает:**
Переходит в папку скрипта и выполняет `docker compose up -d`.

**Использование:**
Запустите `run.bat`, если образы уже загружены и все необходимые файлы (`.env`, `nginx.conf`) находятся на месте.

## Типичный рабочий процесс

1. **Сборка проекта**  
   Запустите `build.bat`, укажите путь к проекту. Дождитесь завершения сборки.

2. **Экспорт образов**  
   Запустите `export.bat`, укажите путь к проекту и путь для сохранения `.tar`-файла (или оставьте по умолчанию).

3. **Перенос на другую машину**  
   Скопируйте `.tar`-файл, а также папку с проектом (или как минимум файлы `docker-compose.yml`, `.env`, `infra/nginx/nginx.conf` и сами скрипты).

4. **Загрузка и запуск**  
   На целевой машине поместите `.tar`-файл рядом со скриптами и запустите `load.bat`.  
   Если образы уже загружены, можно использовать `run.bat` для простого запуска.


## Примечания

- Убедитесь, что Docker Desktop запущен перед выполнением скриптов.
- Скрипты `load.ps1` и `run.ps1` требуют наличия файла `.env` в корне проекта. Если его нет, вы получите предупреждение и скрипт завершится с ошибкой.
- Файл `infra\nginx\nginx.conf` также должен присутствовать для корректного запуска.
- Все скрипты используют `$PSScriptRoot` для определения своего местоположения.
- При возникновении ошибок скрипты возвращают соответствующий код возврата, который отображается в `.bat`-обёртке.
